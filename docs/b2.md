YOUR BRANCH: the surface. React + Convex client in /src. Everything reactive via 
useQuery — NO manual polling, subscriptions update the UI automatically.

Build order by demo value. Build the live execution board FIRST against SEEDED 
runs/messages so the wow works before real agents land.

1. [FIRST] Live execution board: subscribe to runs + messages. Render each running 
   ticket as a node that lights up by status (running -> review -> done), streaming 
   its progress messages live, and showing the PR link when prUrl lands. Parallel 
   nodes updating in real time with no refresh IS THE MONEY SHOT — weight all your 
   polish here. Make the parallelism obvious (they should visibly run at once).

2. Ticket approval board: subscribe to tickets. Show proposed tickets grouped, each 
   showing its assigned agentType (ui/ml/ds/swe as a clear badge). One "Approve & 
   Run" button -> approveTickets then runApproved. THIS is the human-as-PM gate.

3. Epic input: a box to submit an epic -> submitEpic -> proposeDecomposition. Show 
   the proposed tickets appearing.

4. [STRETCH] multi-approver: show N approver checkboxes on the ticket set; only 
   enable Run when all are checked. Trivial boolean gate — only if core is done.

Keep it clean and legible. The judges' eyes are on the live parallel execution — 
everything else is supporting cast. Use the assigned agentType badges to make the 
"specialized agents" story visually obvious.

PRIORITY: 1 (live board) > 2 (approve gate) > 3 (epic input) > 4 (multi-approver).
